# Web Mario Cocos Creator Project

This is the Cocos Creator version of Assignment 02 - Web Mario.

The project is based on Cocos Creator `2.4.8`. The game content is generated by code at runtime, so no manual scene dragging or inspector value entry is required.

## How To Preview

1. Open Cocos Creator.
2. Add/import this folder: `WebMarioCocos`.
3. Open the `main` scene if it is not already open.
4. Press `Preview`.

## How To Build

1. Open `Project > Build...`.
2. Choose `Web Desktop` or `Web Mobile`.
3. Build the project.
4. If you choose `Web Mobile`, the default Firebase config in this folder deploys `build/web-mobile`.
5. Deploy the generated build folder to Firebase Hosting.

## Controls

- Move: `A` / `D` or left / right arrows
- Jump / double jump: `W`, up arrow, or space
- Fast fall in air: `S` or down arrow
- Crouch on ground: `S` or down arrow
- Pause: `P`

## Implemented Features

- Start menu, level select, pause, level clear, game over, and win flow.
- Firebase Email/Password account registration, login, logout, and cloud scoreboard.
- Two side-scrolling levels.
- Gravity, double jumping, fast falling, crouching, and collision against ground, pipes, stairs, bricks, and question blocks.
- Question blocks with coin and mushroom payloads.
- Player life, score, high score, coin counter, world label, progress bar, and timer UI.
- Enemy patrols, enemy damage, and stomp-to-defeat behavior.
- Mushroom power-up.
- BGM and sound effects loaded from `assets/resources/AS2_source/audio`.
- Player walk/jump sprite animation and enemy sprite animation.
- Coin floating animation, question-block bump animation, mushroom rotation, score popups, and stomp smoke effects.
- Local high score is saved with `cc.sys.localStorage`; signed-in players also upload their best score to Firestore.
- All gameplay nodes are created programmatically in `assets/Scripts/GameManager.ts`.

## Scoring Checklist

- Complete game process: start menu, level select, gameplay, pause, game over, level clear, and win state.
- Basic rules: scrolling world, gravity, collision, static walls/floors/pipes/stairs, controllable player, enemies, question blocks, mushroom power-up, out-of-bounds death, and respawn.
- Animations: player running/jumping, enemy animation, coins, blocks, power-up, score popup, and smoke.
- Sound effects: BGM, jump, coin, stomp, hurt/life loss, power-up, item appearance, level clear, and game over.
- UI: lives, score, high score, coins, timer, world name, progress bar, account panel, and scoreboard.
- Appearance: uses the provided Mario assignment assets where available and programmatic Cocos shapes for level tiles/background.

## Source Layout

- `assets/Scripts/GameManager.ts`: main game implementation.
- `assets/resources/AS2_source`: assignment-provided images, fonts, audio, and sprite data.
- `assets/Scenes/main.fire`: Cocos scene entry point.
- `firestore.rules`: security rules for scoreboard writes.
- `settings/project.json`: Cocos project settings.

## Firebase Hosting

Before using accounts and scoreboard in the deployed game:

1. In Firebase Console, enable Authentication > Sign-in method > Email/Password.
2. Create a Cloud Firestore database.
3. Deploy the Firestore rules:

```powershell
cd WebMarioCocos
firebase deploy --only firestore:rules
```

After Cocos Creator finishes building:

```powershell
cd WebMarioCocos
firebase login
firebase deploy --only hosting
```

If you build as `Web Desktop` instead of `Web Mobile`, update `firebase.json` so `public` points to the generated folder.
